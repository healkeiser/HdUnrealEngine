Geometry internals¶

Implementation notes behind the user pages on meshes, subdivision, displacement, Nanite, volumes, fog and sky.

Nanite¶

Meshes from the native asset catalog render with Nanite when their cooked asset has Nanite data (unreal:requireNanite enforces it). Static meshes hdUE builds from Hydra, and instancer prototypes, become Nanite meshes too. Batch renders (husk) build Nanite data and Lumen cards before the first frame; interactive hosts (Houdini's viewport, which start UE with HDUE_INIT_INTERACTIVE) first draw regular static meshes, build both on worker threads, then swap each mesh, one per frame. Those first-pass meshes are full resolution, so they are made smallest first only while their estimated GPU memory stays under r.HdUE.InteractiveFirstPassMemory (2,048 MB; Windows also charges a process's D3D12 allocations to its commit); the other meshes appear when their build is swapped in, as UE draws no static mesh while it compiles (UStaticMeshComponent::ShouldCreateRenderState). Copies of a mesh in later uploads draw its first pass too. The viewport keeps drawing while builds are pending and converges once the last one is in. A mesh's root page stays on the GPU and its other pages stream from system memory when the view needs them, as UE streams a cooked mesh's pages from disk (UE's non-editor streaming reads only cooked files, so Apply-ResidencyPatch.ps1 compiles in the editor's path for pages in memory; building). The pool is UE's (r.Nanite.Streaming.StreamingPoolSize, 512 MB), and a view whose unique geometry overcommits it draws Nanite's coarser clusters, as UE does (r.Nanite.Streaming.QualityScale.*): 16 grids of 1M triangles in a 512-pixel frame differ from fully resident pages by 0.6% of the mean brightness at 512 MB and match them (within run-to-run noise) at 1,900 MB. A Nanite mesh's LOD 0, which draws where Nanite does not and which ray tracing (Lumen's, the Path Tracer) traces, is the Nanite builder's fallback mesh, as UE's static mesh build makes it (BuildNanite, StaticMeshBuilder.cpp), at UE's default relative error (Fallback Target Auto: r.Nanite.Builder.FallbackTargetAutoRelativeError, 1); a mesh that ends up without Nanite (a translucent material, a full root page pool) keeps all its triangles. Identical meshes share one static mesh, as UE's USD importer shares one asset between identical prims (UUsdAssetCache3, keyed by a hash of the mesh, USDGeomMeshTranslator.cpp). Animated or edited meshes stay dynamic. HDUE_NANITE=0 turns Nanite off.

Building Nanite data is most of a scene's mesh conversion, so builds are cached across processes, as UE's derived data cache keeps a static mesh's (FStaticMeshRenderData::Cache, StaticMesh.cpp): one file per mesh in Saved/NaniteCache (under the runtime project, or HDUE_USER_DIR), keyed by the Nanite builder's version, the fallback's relative error and the mesh's vertices and triangles, its streaming pages and fallback mesh appended after the resources, and removed after a week unused. UE's cache itself does not run in a cooked runtime such as hdUE's (GetCache() creates none where RequiresCookedData(), DerivedDataCacheModule.cpp; cooked games get their derived data from the cook, and these meshes only exist at render time). 450 meshes of 9,800 triangles: 10.5 s to build, 0.7 s from the cache (75 MB), the same image. UE keeps all of a scene's Nanite root pages in one GPU buffer of at most 2 GB on NVIDIA (4 GB on AMD) less its 512 MB streaming pool, and ends the process when one more does not fit; each mesh keeps one root page there, so it holds tens of thousands of meshes; hdUE stops attaching Nanite data at 90% of that pool and renders the remaining meshes as regular static meshes, with a warning in UE's log. In Houdini's viewport the card and Nanite builds start while their memory fits, as UE's editor schedules asset builds (FMemoryBoundQueuedThreadPoolWrapper, AssetCompilingManager.cpp): each is estimated at 7 times its mesh data (UStaticMesh::GetBuildRequiredMemoryEstimate) and holds that until its mesh is swapped in. r.HdUE.MeshBuildMaxMemoryUsage (GB, 0 by default) caps them below the available memory, as UE's Editor.AsyncAssetCompilationMaxMemoryUsage does. In a Windows job with a memory limit (a farm container), the available memory is the job's: the runtime sets UE's memory.WindowsPlatformMemoryUseContainerMemory.

This sets the scale hdUE renders from Hydra geometry. NVIDIA's Da Vinci Workshop (617M triangles, 6,750 meshes, of which 1,700 distinct) renders under husk at 960 x 540 in the realtime mode with a job memory peak of 22 GB: 11 minutes with an empty Nanite cache (3.6 GB written), 2 minutes from it (see architecture). Its lights are bright (exposure 1 to 7 on intensities of 100 to 2,000) and its camera authors no exposure, so the image needs an exposure of its own. In Houdini's viewport, in render purpose, it converges in about 3.5 minutes with a job memory peak of 30 to 33 GB. UE's own runtime USD import of the shot passed 62 GB, and its editor import crashes on one of the scene's UDIM textures. Cooked UE static meshes referenced through unreal:asset (cooked native assets) keep their geometry out of the host: their pages stream from their cooked files, as in a UE project.

Displacement¶

The Preview Surface displacement input and MaterialX ND_displacement_float (displacement × scale) move the mesh's points along their normals by that distance, in the mesh's object space and units, before the mesh is uploaded, so Lumen, the Path Tracer and Nanite see the same surface. A textured displacement first dices the mesh uniformly: each triangle splits into four per level, up to about one triangle per two texels and at most about a million triangles per mesh. Normals are then recomputed from the displaced surface; a UV seam splits the surface only where the texture differs across it, and hard edges open. A constant displacement moves the points without dicing. Meshes with wet-surface effects are not displaced. Displacement is not adaptive (Karma dices by screen size). UE's Nanite tessellation and World Position Offset are not used: UE 5.8's ray-traced geometry, which the Path Tracer renders, ignores both. MaterialX vector displacement is not translated.

Dicing is HdUEDiceLevels in src/hydra/displacement.h: levels until the triangle count reaches \(\min(\text{texels} / 2,\ 2^{20})\).

Meshes and instancing¶

Generic Hydra translation supports meshes, cameras, materials, and distant, sphere, rect, disk, cylinder, and dome lights.

Meshes reach UE indexed: the triangle corners of a point share one vertex unless a face-varying normal, UV, color or wet mask differs between them, so UE holds about as many vertices as the USD mesh has points. A mesh UE cannot take (more than about 715 million vertices, or broken indices) is skipped with a warning naming it in the UE log; the rest of the scene still loads.

Material-binding GeomSubsets partition triangles by their original USD face while preserving UVs, normals, transforms, visibility, and picking paths. Unassigned faces retain the mesh material; overlapping or invalid material subsets are rejected. Subset edits and removals update the generated meshes.

Meshes follow USD's doubleSided, as UE's USD importer does: single-sided meshes draw a one-sided twin of their material and cull their back faces. unreal:cullBackface = 0 renders every mesh on both sides, as Karma does (its karma:object:cull_backface defaults to off). Karma's per-object karma:object:cull_backface primvar is not read; doubleSided is the per-mesh switch.

Missing or zero normals are generated from area-weighted vertex adjacency before subset partitioning, so material boundaries share the same shading normals. Authored normals are retained. Author explicit face-varying normals or split vertices where hard edges are required; normal generation does not apply subdivision creases.

Hydra instancers (USD PointInstancers, including nested ones) are translated: each prototype mesh is built once as a runtime static mesh, or uses its native cooked asset, and drawn through one instanced static mesh component with per-instance transforms composed as in hdEmbree. Preview Surface and ID materials are cooked with instanced-static-mesh usage; prepared MaterialX or Substrate materials need that usage too before they render on instances. Instanceable references (USD native instancing) reach the delegate as Hydra instancers too, in Solaris as elsewhere. Instances hidden by invisibleIds or deactivated by inactiveIds are not drawn (Hydra leaves them out of the instance indices), orientations (half) and orientationsf (float) are normalized as UsdGeomPointInstancer does, an instance-rate primvar that a bound Preview Surface's base colour reads through a primvar reader colours each instance (as an unbound prototype's displayColor does), and volumes under an instancer are drawn once per instance (sharing one density grid on the Hydra side). UE instances are FTransforms, which hold no shear, so instances whose transform shears (a rotated prototype under a non-uniform instance scale) are baked into the vertices of one companion mesh per prototype, as a sheared mesh outside an instancer is; the others stay UE instances (instancer/shear). With motion blur, the companion is baked again per sub-frame. A prototype with a native cooked asset has no vertices to bake, so its sheared instances render without shear, with a warning.

Implicit Cube, Sphere, Cone, Cylinder, Capsule and Plane prims are converted to meshes by Hydra's implicit-surface scene index (HdUE_ImplicitSurfaceSceneIndexPlugin), as for hdEmbree.

Points render as one shared sphere instanced per point, sized by widths (0.1 when unauthored). BasisCurves render as six-sided tubes with flat end caps on open curves: linear curves follow their vertices, cubic Bezier, B-spline and Catmull-Rom curves are evaluated in their basis, and widths set the diameter (0.01 when unauthored). Points and curves under a PointInstancer are drawn once per instance.

Hair. BasisCurves with the constant primvar primvars:unreal:groom = 1 (Hydra passes curves their primvars, not other attributes; Hair Strands on the Unreal Engine tab of Render Geometry Settings LOPs, on the curves or an ancestor) render as UE hair strands instead of tubes: hdUE builds the groom asset UE's importer would make, with UE's own groom builder, from the evaluated curve points and per-point widths: one group, guides generated from every strand (no simulation), drawn by a groom component with UE's default hair material, in realtime and in the Path Tracer (its strand geometry). Instanced grooms and hair colour, root UV and per-strand attributes are not translated yet.

Mesh UVs come from the primvar that the bound material's UsdPrimvarReader_float2 reads (varname, such as st, or map1 from 3ds Max exports), or from st when the material names none. Each texture reads the UV set its own st input names (also through a UsdTransform2d): the mesh carries every UV primvar its material reads, up to four, chosen through its own binding (else its first bound GeomSubset's). The UV transform is still one per material, from the first textured input.

Unbound geometry uses displayColor/displayOpacity. A displayColor that varies (uniform, vertex or face-varying on meshes, per point on Points, per vertex or per curve on BasisCurves, per instance on a PointInstancer, from the nearest of nested instancers that authors it) is multiplied into M_PreviewSurface as vertex colors or per-instance custom data. Dynamic mesh vertex colors are stored in 8 bits, so very dark colors band slightly. Varying displayOpacity, and colors on meshes that also carry a wet-surface mask (the mask reuses the vertex colors), are not translated. The unbound default is a Preview Surface (roughness 0.5) whose base colour is displayColor, as UE's USD importer draws unbound prims (its DisplayColor reference material feeds the vertex colour straight into Base Color); a prim with no displayColor is white, the vertex colour UE's importer gives it (Karma draws such prims grey).

Volumes¶

Volumes (Houdini build) render the density field, or the first field, of a Volume prim as a UE heterogeneous volume with M_HdUEVolume (albedo 0.8; density is extinction per scene unit). The field can be:

  • an OpenVDBAsset pointing to a .vdb file, read with OpenVDB;
  • an unsaved SOP volume in the Solaris viewport: OpenVDBAsset or HoudiniFieldAsset prims whose filePath is an op: SOP layer. hdUE takes the cooked geometry from Houdini's locked-geometry registry, or cooks the SOP;
  • a .bgeo / .bgeo.sc file, which is where the USD Render ROP writes native Houdini volumes for husk.

From Houdini geometry, the VDB or Houdini volume primitive named after fieldName is used, else the fieldIndex-th one. Grids are densified over their active bounding box and point-sampled with a stride above 512 voxels per axis. A bound Substrate Builder volume material replaces M_HdUEVolume in Houdini's viewport (volume materials); other volume materials, tapered Houdini volumes and frustum VDBs are not translated.

Emission. The constant primvar primvars:unreal:emissionField on the Volume prim (Hydra passes a volume its primvars, not other attributes; Houdini detail attributes become them) names another of its fields (temperature, flame, ...) that emits light: UE's BlackBody of the field's value times primvars:unreal:temperatureScale (kelvin per unit, 1 by default), times primvars:unreal:emissionIntensity (1). The field is sampled at the density's voxels (nearest voxel, 0 outside its own grid). As in UE, nothing emits unless asked: UE's heterogeneous volumes emit what their material makes of an imported grid, and UE prescribes no field or mapping. Both modes render it.

Measured against Karma: in realtime, a fog's brightness is within about 15%. Volumes shadow the scene in both modes. In realtime this is UE's heterogeneous volume Shadow Casting (r.HeterogeneousVolumes.Shadows, on in this project), with one shadow projection fitted around the volumes (r.HeterogeneousVolumes.Shadows.Cascades 0: with Virtual Shadow Maps, UE's default single cascade left the volume's shadow map empty). As in UE 5.8, the shadow reaches lights shaded by UE's deferred light loop: distant lights, and local lights with unreal:megaLights off (MegaLights does not support heterogeneous volumes); a light also needs Cast Volumetric Shadow (unreal:light:bCastVolumetricShadow, on by default for distant lights). The Path Tracer casts it (optical depth 1.4 against Karma's 1.9) and includes multiple scattering. It re-voxelizes volumes for each frame; batch renders use the shading rate 1 and 512 MB that UE's docs recommend for cinematic renders (r.HeterogeneousVolumes.{Frustum,Ortho}Grid.ShadingRate, .MaxBottomLevelMemoryInMegabytes; 4 and 128 MB by default, which made silhouettes blocky).

Fog, sky and clouds¶

The Fog tab of hdUE Render Settings places UE's Exponential Height Fog in the scene, as an Exponential Height Fog actor does in a level. Exponential Height Fog (unreal:heightFog) turns it on; Fog Height (unreal:heightFogHeight, scene units along the stage's up axis) is the actor's height, where the density is Fog Density. Every other parameter is a UExponentialHeightFogComponent property (unreal:heightFog:<Property>), generated from the engine source with UE's categories, names, ranges and defaults; distances are in UE centimeters, as in UE's Details panel. UE's USD importer imports no fog, so there is no USD schema to follow.

Volumetric Fog (unreal:heightFog:bEnableVolumetricFog) gives lit, shadowed fog and light shafts: lights scatter into it by their Volumetric Scattering Intensity. UE's Path Tracer renders the height fog only with Volumetric Fog on (PathTracing.cpp), and limits its density growth below the fog height with r.PathTracing.FogDensityClamp. The fog is part of the scene, so colour AOVs show it too. Changing a fog setting rebuilds the fog, which restarts volumetric fog's temporal history.

Scene prims for fog, sky and clouds¶

The height fog, sky atmosphere and clouds can also be placed by prims, as their actors are placed in a UE level, so they live in the scene rather than in the render settings: UnrealExponentialHeightFog, UnrealSkyAtmosphere and UnrealVolumetricCloud (codeless schemas in resources/generatedSchema.usda, generated with the same properties as the render settings' tabs, with UE's constructor defaults as fallbacks). Their attributes are the render settings' names: unreal:heightFog:<Property>, unreal:skyAtmosphere:<Property>, unreal:volumetricCloud:<Property>. A prim takes the place of its render settings counterpart (whose switch and properties are then ignored); UE draws one of each, so the first visible prim of a kind by path is used. A height fog's height is the prim's world position along the up axis (its density is Fog Density there), as an Exponential Height Fog actor's Z; a sky atmosphere's position counts only when its Transform Mode places the planet at the component. hdUE Height Fog, hdUE Sky Atmosphere and hdUE Volumetric Cloud (TAB menu > hdUE > Visual Effects) create or edit them, with the render settings' Fog and Sky properties, each at Do Nothing (the prim's fallback, UE's default) until turned on. render_settings/height_fog_prim checks the fog, its height and that the prim wins over the render settings' fog; render_settings/sky_atmosphere_prim the sky and, in realtime, the clouds.

Local fog volumes¶

An UnrealLocalFogVolume prim is a UE Local Fog Volume: a sphere of fog that fades out radially, combined with a height fog along its up axis. hdUE Local Fog Volume (TAB menu > hdUE > Visual Effects, integrations/houdini/otls/hdue_localfogvolume.hda) creates or edits one, as Karma Sky Atmosphere does Karma's sky: a primitive path, Houdini's transform section (Uniform Scale is the radius, 1 by default: UE's volume is a sphere of radius 500 cm, scaled uniformly), and UE's properties, each with a control menu. In Create mode every property is authored, at UE's defaults too (Houdini's viewport is not told about an attribute added to an existing prim, so one authored only once changed would not update it); Edit mode changes existing prims (Houdini). The prim type is a codeless schema shipped with the delegate (resources/generatedSchema.usda, generated by scripts/generate_render_settings.py from ULocalFogVolumeComponent): an Xformable whose attributes are unreal:localFogVolume:<Property>, with UE's defaults as fallbacks. The unit sphere of the prim's local space is UE's base volume; its local up axis is the stage's.

As in UE:

  • Local fog volumes render in realtime only; UE's Path Tracer ignores them.
  • UE draws none nearer than 10 m to the camera (r.LocalFogVolume.GlobalStartDistance, in Engine Quality's console variables or as unreal:cvar:r:LocalFogVolume:GlobalStartDistance); a volume's own Start Distance can only push it further.
  • Height Fog Density 0 hides the whole volume: UE combines the radial and height fog as the product of their coverages (LocalFogVolumeCommon.ush), so use a small value for radial fog alone.
  • With Volumetric Fog on the height fog, the volumes are also lit and shadowed through it (r.LocalFogVolume.RenderIntoVolumetricFog).

The Sky tab places UE's Sky Atmosphere and Volumetric Cloud, as their actors do in a level. Sky Atmosphere (unreal:skyAtmosphere) turns on UE's physical sky; every USkyAtmosphereComponent property is unreal:skyAtmosphere:<Property>, generated like the fog's (UE's atmosphere is in kilometres, its planet top at the world origin by default). Distant lights light it as Atmosphere Sun Lights, UE's default for a directional light (unreal:light:bAtmosphereSunLight, index 0 the sun and 1 the moon). Without a DomeLight, hdUE adds a Sky Light with Real Time Capture so the sky lights the scene, as UE's default level has: Lumen needs it, and UE's Path Tracer renders the atmosphere only through it (or with Reference Atmosphere, Path Tracing tab). A DomeLight's environment takes its place.

Volumetric Cloud (unreal:volumetricCloud, unreal:volumetricCloud:<Property>) needs the Sky Atmosphere. Its default material is UE's /Engine/EngineSky/VolumetricClouds/m_SimpleVolumetricCloud_Inst, cooked with the runtime from this version on (a runtime staged before has no cloud material); unreal:volumetricCloud:Material takes another cooked material. UE's Path Tracer renders clouds with Reference Atmosphere on.
