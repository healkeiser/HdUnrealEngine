Execute in the order below unless the dependencies say otherwise. Each executor: read the plan fully before starting, honour its STOP conditions, and update your row when done (unless your reviewer maintains this index).

## Execution lanes

Two lanes run side by side, because UE backend builds need ~13 GB per checkout and GPU tests cannot share the GPU:

- **Main lane** (the main checkout, `main`): plans that build C++ (backend, delegate, host), regenerate HDAs or need GPU, husk or Houdini tests. One plan at a time.
- **Side lane** (worktree `..\hdUE-side`, a sibling folder of the repo, branch `exec/side`): plans that change only Python, PowerShell or docs and verify with `Test.ps1 -Suite unit` and the formatters. No GPU, husk, hython or Houdini runs; GPU checks they need are run in the main lane at the review points.

Review points: a review of each plan's diff before it lands; a mid-point review of everything landed (after plan 016); an end review of everything.

## Decisions the plans stop and ask about

- 019 Step 3: which console variables a scene file may still set (`bridge.h` documents `set_post_process` as accepting any cvar). **Decided (2026-11-14): scenes keep setting any console variable**, as UE's Movie Render Queue lets a render configuration set any cvar (Unreal is the benchmark); 019 closes the memory-safety risk instead, by refusing scene-set properties that are not editable (`CPF_Edit`).
- 020 Step 4: whether husk stops auto-preparing materials for scenes by default. **Decided (2026-11-14): keep the default.** husk preparing unprepared Substrate graphs is a deliberate feature (`7830f22`), and the setting comes from the hdUE Render Settings LOP; the exploit (finding `pwsh` through the current directory) is fixed by 020's process-launch steps.
- 027 Part A: default UsdUVTexture wrap (UE's repeat vs the spec's black) and where scene-linear colours are converted. **Decided (2026-11-14):** D1 option (b), unauthored `wrapS`/`wrapT` repeat and `useMetadata` clamps as UE's USD importer reads them, an authored `black` stays true black; D3 option (a), colours convert from `scene_linear` to linear Rec.709 everywhere with the same OCIO processor (done for varying vertex and instance colours and prepared MaterialX colours; live native-material parameters are a follow-up below).

## Findings considered and rejected

- `render_gallery.py` writes `results.json`, `README.md` and `gallery.md` non-atomically: single-user tool, git restores them.
- HDAs change bytes on every rebuild: binary format, unavoidable.
- `Runtime.State` and `Session->Width/Height` read without a lock (`Bridge.cpp`): formally a data race, harmless on x64, the `DepthPixels.Num()` check catches a mismatch.
- `set_post_process` accepting any console variable: documented as by design in `include/hdue/bridge.h`; scenes keep it too (plan 019 Step 3 decision: Movie Render Queue lets a render configuration set any cvar).
- NURBS resampling knot vector one element short (`implicit_surfaces.cpp:173-176`): the approximating scene index draws the hull without reading knots.
- Render-buffer pointer reuse skipping GPU setup (`delegate.cpp:2120-2138, 2826`): low confidence; left for a reproduction before any fix.
- Blocking texture-streaming flush on every offline realtime warm-up draw (`Bridge.cpp:1332-1344`): Movie Render Queue does the same on every tick (`MoviePipelineRendering.cpp:174`), so hdUE matches Unreal.
- Sheared-instance product cap: already capped by `HdUEBakesShear` (`delegate.h:162-168`).
- Subdivision-level change marking every mesh dirty (`delegate.cpp:4055-4057`): a global level change does affect every mesh; only the `surfaceEffects` loop is wasteful (plan 023).

## Mid-point review (2026-11-14)

All work up to plan 016 was verified at `8e389b6`: every build and test tier, a full conformance run (361 runs, 0 failing), the Houdini and usdview suites, and Cornell against the installed v0.5.0 release (Path Tracer identical, realtime 0.1%). Four independent reviewers read the whole diff. Their findings were fixed in two batches (C++ `5987376`..`bbf3a2c`; Python and PowerShell `e1f1915`..`199d85f`), among them: husk again fails a frame when a required native mesh cannot draw; motion samples of changing sizes are no longer interpolated; cancelling an asset import ends the whole cook process tree; a ratio of two black probes fails; picking no longer depends on iteration order.

Found and left open:
- UE collected garbage only inside the world tick, which Path Tracer requests pause. Fixed (`23a6250`): the stopped world collects on UE's own schedule (`ConditionalCollectGarbage`), as the editor does while its viewport path traces; the accumulated image is unchanged.
- Skip warnings were kept once per process and reached only the console in Houdini's viewport. Fixed (`1c55435`, `433ed17`): they are kept per session and listed in the render stats overlay; husk still prints each once.
- Native picking waiting for queued UE work: no change needed. Only usdview calls `unreal:pickRay`, on UE's own thread; Houdini's selection reads the ID buffers and never waits on UE.
- The auto viewer light lighting emissive-only scenes: Houdini's rule (a headlight only when the scene has no light prims; emissive materials are not lights). The docs say so (`81df4cb`).
- `abi_mirror_test.py` compared struct sizes, not field offsets. Fixed at the end review (`bf4bd06`).

## End review (2026-11-14)

Every plan was done at `2b834e7`. Independent reviewers read the whole diff since the audit in three lanes (backend C++, delegate C++, scripts, tests and docs). No finding was critical. All were fixed except one:
- Backend (`02b3860`..`3ce6286`): an ID pass compares a mesh's override slot, not its resolved material; a batch instance move updates the instancer's bounds and leaves ID mode first; a reused Path Tracer warm-up reports the current request's generation; scene object values may name mounted plugin content.
- Delegate (`bf4bd06`..`8c3d743`): the ABI mirror test compares field offsets; the subdivision cap is a render setting with UE's default (`maxSubdivisionLevel`, 6); an animated mesh in husk moves without re-reading its geometry; asset bounds re-read the profile and catalog when they change; one warn-once helper names its material or AOV, and husk fails a short AOV frame; live colour parameters convert from `scene_linear`.
- Scripts, tests and docs (`4489b6a`..`3c8e579`): prepared MaterialX images decode as the render-time translation does; an input authored at its default no longer sends a graph to UE's importer; the content copy survives a killed or concurrent import; checks that could not fail now can (an ACES config, 50 % screen percentage, the dome fallback, two MaterialX values, the gallery's largest tile); the extended tier binds each kind's prepared library.
- Rejected: a reported data race in the backend through `copy_buffer` and `HasRequest`. No `copy_buffer` exists, and `HasRequest` is already atomic.

The final check rebuilt everything and re-prepared the stale libraries. `Test.ps1 -Suite all` passed. The full conformance run passed: 366 runs, 184 scenes in both modes, 0 failing. Cornell matched the installed v0.5.0: the Path Tracer was identical in 14 scenes, `volume` differed 0.35 % in noise only, and realtime was within 0.30 %. The extended tier's failures were test faults, fixed in `efccfcd`, `66c7fa5`, `a032cfe`, `e79958c` and `8f6a264`:
- the selection test's Sun covered the click in a portrait viewport;
- the usdview scene check needs an unlit scene for viewer lighting;
- the Substrate tests treated background preparation as an error and lost the Path Tracer mode;
- the image-change check counted the whole view, not the pixels showing the scene.

The same tier then crashed `decal` once, in UE's start-up: call-stack tracing walks the loaded modules without the loader lock while Houdini unloads one. It is compiled out (`fce1f9a`).

Two more were fixed during the final runs. Houdini's viewport overlay read 0 Path Tracer samples until the render ended (reported by the maintainer): the shared GPU frames it shows carried no sample count (`60f1044`). The `substrate-live` test could take its first image while the preparation it had just switched on was running (`d54f255`).

On the final build, `-Suite all` and the extended tier pass, and the Cornell gallery passes every scene in both modes (glossy's Lumen tile baseline re-blessed, its brightness band widened to 1.3).
