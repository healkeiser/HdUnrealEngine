## Why this matters

hdUE translates simple MaterialX graphs itself at render time (`src/hydra/materials.cpp`). Graphs it cannot express go to UE's MaterialX importer instead (the "prepared" path), which follows the MaterialX library exactly. Four render-time rules disagree with the MaterialX library that ships with Houdini 22, so the same material looks different at render time and once prepared:

1. `tiledimage` adds `uvoffset`; MaterialX subtracts it. Textures shift the wrong way.
2. `standard_surface` uses version 1.0.0's defaults (`base` 0.8, `base_color` 1). The default version is 1.0.1 (`base` 1.0, `base_color` 0.8). A material that authors only `base_color` (the usual case) renders 20% darker.
3. An unauthored `multiply` input is treated as 1. MaterialX's default for `in1` is 0.
4. `normalmap`'s `vector2` scale is ignored (read as 1).

After this plan, render-time results match the MaterialX definitions, and four conformance checks guard them.

T value(const VtValue& v, T fallback) {

`ND_normalmap_vector2` has a `vector2` scale (`stdlib/stdlib_defs.mtlx:2875-2882`, `<input name="scale" type="vector2" value="1.0, 1.0" />`); `value<float>` of a `GfVec2f` returns the fallback 1. `ND_normalmap_float` (`:2867-2874`) has a `float` scale and works today.

Conformance scenes: each scene's `customLayerData["conformance"]` is a JSON string with `"checks"`. `scripts/run_conformance.py:248-280` (`verify`) supports `"log"` (regex in husk's output, `"present": false` for absence), `"value"` (one probe, `min`/`max`), `"ratio"` (two probes, `min`/`max`) and `"color"`. **Do not use `"color"` to test brightness**: it divides RGB by its sum, so any grey matches any other grey. Use `"ratio"` between two quads; the key light is a distant light, so flat quads facing the camera get the same light anywhere. Exemplar of a `ratio` check: `samples/conformance/preview_surface/normal_map.usda:11-33`.

Translation choices follow the repo rule: what Unreal does first (its USD importer and Interchange MaterialX importer), then the USD/MaterialX spec, then Karma. UE's Interchange importer imports these nodes through MaterialX's own node graphs and nodedefs, so the MaterialX library is both "what UE does" and the spec here.
