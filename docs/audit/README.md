# hdUE audit (2026-10-29)

An audit of hdUE (`feature/package`, `e8fe1f4`) against the OpenUSD/Hydra, SideFX Houdini 22 and Unreal Engine 5.8 documentation and the public source of reference delegates (HdEmbree, HdStorm, HdArnold, hdPrman, hdCycles). Every finding cites the code (`path:line`) and the document it is measured against; points that could not be checked by reading code or running a test are marked *unverified* or *inferred* in the reports.

Reports 01–05 measure hdUE against the documentation: what is wrong or missing. Reports 06 and 07 are code-quality passes over the whole tree (at `3d65669`): 06 lists what to delete or replace with stdlib/USD/platform features, 07 lists reuse, simplification, efficiency and root-cause fixes. Correctness comes first; [Cleanup](#cleanup-06-07) summarizes 06 and 07.

## Act first

Spot-checked against the code while consolidating; all held.

1. **Licensing: pull or privatize the public release zips (UE-01, UE-02, UE-03, PKG-01).** v0.1.0 and v0.2.0 are public GitHub releases (~950 MB each). The backend DLL contains Developer ("Engine Tools") code: `bBuildDeveloperTools = true` (`unreal/HdUEBackend/Source/HdUEBackend.Target.cs:16`) and `NaniteBuilder` (`HdUEBackend.Build.cs:10`). EULA §6(d) restricts distribution of such products to Fab or forks of Epic's UnrealEngine GitHub network. The zip also carries no EULA end-user terms, no Epic notices and no third-party licences, next to a bare MIT `LICENSE`. Not legal advice: confirm with Epic before the next release.
   *Status (2026-10-29):* both zip assets deleted, release notes say why; `Package-Houdini.ps1` now ships `LICENSE-PACKAGE.txt` (end-user terms), `THIRD_PARTY_NOTICES.md` and the engine's third-party licenses, drops the smoke exe, import libraries and debug layers, and refuses to package Developer code without `-UnrealLicenseesOnly`. Open: removing the Developer code itself, and the seat status of the developing entity (§6(a)).
2. **Crash risk in the Solaris viewport (HYD-01).** The Execute posted to the UE thread keeps a raw `HdCamera*` and render buffer pointers (`src/hydra/delegate.cpp:986-1000`) and reads them after Houdini may have synced or deleted them. Copy the camera values and own the buffers in the snapshot.
3. **IES lights ~1000x too dark (LGT-01, LGT-03, UE-12).** `bUseIESBrightness=false` (`Lighting.cpp:214`) discards UE's candela peak, and `TextureMultiplier` is always 1, so `normalize` is a no-op. Multiply by the profile's brightness. One-line fix; explains the 0.00 in the gallery.
4. **Purpose and render tags ignored (HYD-02).** `executeOnce` drops its tags (`delegate.cpp:1060`): proxy/guide geometry renders, toggles do nothing.
5. **Silent black outputs (HYD-03, HYD-06).** A `color3f` beauty (UsdRenderVar's default type) or any AOV with a channel-count mismatch is dropped without a message. `lpe:` vars get a copy of the beauty.
6. **husk robustness (HOU-03, HOU-06, UE-05).** UE cannot restart after the last delegate goes away outside the GUI (`delegate.cpp:1567-1579`), `huskErrorStatus` is never set so failed frames exit 0, and frames can be written with placeholder materials while PSOs compile.
7. **Path Tracer motion blur wastes samples (UE-04).** The seed is locked (`Bridge.cpp:442`) and each sub-frame restarts the view state: 512 spp over 16 sub-frames is 32 spp on static pixels. Offset the seed per sub-frame as Movie Render Graph does.
8. **Cost on every Houdini session (HOU-01).** The package loads both DLLs and runs a 16 ms timer and a 2 s disk write even when hdUE is never picked. Start the host when a viewport selects hdUE.
9. **Houdini build pinning (BLD-01).** The plugin is built against one 22.0 daily build but loads into any 22.0.x without an ABI check, and the repo disagrees on which build (22.0.466 vs 22.0.368).
10. **Tests that lie or don't run (TST-01, TST-02, TST-03).** `Verify.ps1` writes `passed = $true` and constant counts; 23 Python tests that pass outside Houdini are not in CI; no image baselines, which is how a black IES scene shipped in the gallery.

Fourth round (2026-10-31):

- **Viewport/husk look:** not hdUE and not UE's editor-vs-MRQ quality. The viewport's frame is 1.03x husk's on Cornell (tonemapper on) and the offline profile changes it by 2%; Houdini 22.0.368's viewport OCIO display shows linear values under ~0.004 as black where OCIO's own CPU and GPU transforms are exact sRGB ([rendering](../rendering.md#unreal-post-processing), `Launch-Houdini.ps1 -TestKind parity`).

- **husk cost (item 2):** Nanite builds cached across processes (`Saved/NaniteCache`, keyed as UE's static mesh DDC; UE's own DDC does not run in a cooked runtime): 450 meshes, 10.5 s -> 0.7 s. husk's EXR writing measured and documented ([houdini](../houdini.md#performance)); the readback stays float. Viewport card/Nanite builds are memory-bound as UE's editor schedules asset builds (`r.HdUE.MeshBuildMaxMemoryUsage`). A race on the Nanite builder's version string, which corrupted the heap (3 crashed husk renders in about 340 today, in Nanite rendering), is fixed.
- **Staging (item 5):** `Update-HoudiniRuntime.ps1` refreshes the runtime's unhashed `HdUEBackend.dll`, so `.local/runtime.json` passes the ABI check too.
- **Defaults after UE:** `unreal:subdivisionLevel` defaults to 0 (UE's USD Stage Actor `SubdivisionLevel`); scenes that want smooth subdivision surfaces author it (the Cornell gallery and the subdivision conformance scenes do). The viewport's display purposes are no longer narrowed by the stage's `includedPurposes`.
- **Heavy scenes:** NVIDIA's Da Vinci Workshop (617M triangles) exceeds 48 GB in hdUE's viewport with its render purpose; Karma XPU holds it in about 37 GB, UE's own runtime USD import passed 62 GB, and the UE editor's import crashes on a UDIM texture. Houdini alone holds about 40 GB once a delegate has pulled every mesh. hdUE's own copies were cut: mesh rprims no longer cache a triangulation for wet masks (~16 bytes per triangle of every mesh), the upload is sent in ~1 GB batches instead of one packet copying the whole scene, UE's static meshes keep no CPU copy, and change detection compares a geometry hash. Uploads stream during Hydra sync and each static mesh's copy is freed once UE has it (husk, hython and Houdini's viewport); material, visibility and sidedness edits then reach UE through `update_meshes` (C ABI 13) without the geometry, which is re-pulled from Hydra only when UE needs it. Houdini's viewport picks from the ID AOVs UE renders, so it needs no ray picks through UE, and frees its copy too: it never syncs an rprim the render pass marks dirty, so the render pass now re-syncs a mesh UE needs again itself (`HdUERepullMeshes`). usdview keeps its copy for its CPU ray picks. A re-pull used to find the mesh unchanged and never re-upload it; it now always uploads. A full Nanite root page pool no longer ends the process (the remaining meshes render without Nanite). The shot still exceeds UE's runtime limits on a 24 GB GPU (Nanite pages cannot stream for runtime meshes).
- **Ambient Cubemap (item 4): a UE 5.8 bug, documented as a limitation** ([rendering](../rendering.md#unreal-post-processing), [repro](../../samples/repro/ambient_cubemap/README.md)). `AmbientCubemapComposite.usf` never defines `SUBSTRATE_LOAD_FROM_MATERIALCONTAINER`, so with Substrate's adaptive GBuffer (`r.Substrate.ProjectGBufferFormat=1`, UE's default on SM6 and hdUE's) it reads the legacy GBuffer, which that format does not write, and adds nothing; the other Substrate composites define it from `SUBSTRATE_GBUFFER_FORMAT` (`ReflectionEnvironmentPixelShader.usf:25-32`). Bisected in a stock UE 5.8 editor: SM5 renders the cubemap (mean 0.236 at intensity 10, Substrate on or off, with Lumen, MegaLights, VSM, virtual textures or hdUE's Substrate format); SM6 renders 0 with the adaptive GBuffer (also with ray tracing and the Path Tracer) and 0.236 with the blendable one (`ProjectGBufferFormat=0`); an SM6 capture with a point light renders (39.99), so the capture itself works. No configuration fixes it without the blendable GBuffer, which limits Substrate to one closure per pixel.
- **Wet surfaces in the viewport:** a `surfaceEffects` change now re-uploads meshes that become wet (a static mesh made wet failed `apply_surface_effects`). The in-Houdini surfaces test (`-TestKind surfaces`, `samples/wet_surface/showcase.usda`, a library from `Import-MaterialX.ps1 -Source samples\materialx\standard_surface.mtlx -WetProfile`) passes. It timed out at step 03 because it wired its wet override from the hdUE settings node, past the Render Settings LOP, which dropped the Path Tracer mode; it now chains from the displayed node. A static mesh made wet re-uploads dynamic, and the backend's swap of the mesh component reset its geometry revision, so the wet binding of that upload was rejected as obsolete (`apply_surface_effects failed (-7)`, 3 runs in 4 once the viewport freed meshes); the revision now survives the swap.
- **Tests:** `Test-Houdini.ps1` ran its hython tests without the repository's `HOUDINI_PATH`, so `render_outputs_test` loaded an installed package's older HDAs and failed; it now puts `integrations/houdini` first, as `Launch-Houdini.ps1` does.
- **Tests:** `scripts/surface_api.py` bound the runtime's `get_status` instead of `get_surface_status` since the single API table (ABI 12), which crashed the wet surface test.

Open:

- **Needs a decision:** UE-01/UE-03 (Developer modules, EULA: ask Epic), UE-09 (ship a Test build: rebuild and re-cook), UE-15 (Cryptomatte needs our own id AOV and manifest; husk writes it only for Karma), `doubleSided` default (USD culls, Karma does not), shear in instances, instance motion from time-sampled positions and `angularVelocities`. Nanite page streaming for runtime meshes (Da Vinci, below): an engine-side change of UE's streaming manager, which reads pages only from cooked bulk data; start it only on the user's go-ahead. Ambient Cubemap (below): the fix is the missing define in `AmbientCubemapComposite.usf`, a third engine edit next to `Apply-ResidencyPatch.ps1`'s two (or a commit on the engine fork, ALT-11), plus re-cooked global shaders.
- **Da Vinci Workshop (heavy-scene item): documented as the limit** ([rendering](../rendering.md#nanite)). On a 24 GB GPU it exceeds UE's runtime limits: every page of a runtime Nanite mesh is a root page, the root page pool holds at most 2 GB, and the remaining meshes fall back to regular static meshes. UE does no better: its runtime USD import passed 62 GB, and its editor import crashes on a UDIM path (`T_Albedo_`). Heavy-scene tests run only under a 48 GB job memory cap.
- **Not feasible as specified:** MAT-05 (`transparent` opacity renders dark in UE's Path Tracer; Karma renders it like `presence`), HYD-15 far clip (UE's Path Tracer ignores a finite far plane), `hdue:asset` on Xform/Scope and cooked MaterialX/Substrate preparation in husk (host-only Python), ALT-04, ALT-12.
- **Remaining:** ALT-10/11 (wait for UE-01).
- **PSO cache (item 6):** re-recorded after VSM and the material changes (106 PSOs); a Cornell husk render compiles none on the render thread in Lumen or the Path Tracer.
- **Path Tracer direct light (was "floor black at `PathTracingMaxBounces=1`"):** no longer reproduces. Cornell at `PathTracingMaxBounces=1` against a 128-pixel Karma CPU card with `diffuselimit=0`: back wall 1.00x, short box top 0.80x, floor 0.85x, red wall 0.84x. Only surfaces seen at a grazing angle are darker, so the remaining gap is the BSDF's view-angle response (Substrate against Karma's UsdPreviewSurface), not light sampling.
- **Path Tracer "darker floor" (item 3): closed, not a bug.** The test scene's floor and wall had no material binding, so each renderer drew its own fallback albedo: hdUE's was 0.7 grey (now 1, the vertex colour UE's USD importer gives such prims), Karma's 0.5. Against an analytic Lambert reference at the floor's centre that gave 1.34x for hdUE and 0.84x for Karma: the fallbacks differed, not the light transport. With the same Preview Surface bound in both, hdUE matches analytic Lambert within 1-3%, and UE's rough diffuse (EON: `Diffuse_EON` in `BRDF.ush`; `r.Substrate.RoughDiffuse=1` is UE's Windows default, `BaseWindowsEngine.ini`) within 1%; Karma matches Lambert within 1%. On Cornell the back wall's centre is the same in both (0.0469 hdUE, 0.0466 Karma); the gaps left at grazing angles are EON against Lambert, UE's diffuse model against Karma's. Lowering the RectLight 8.7 cm changes the floor by at most 2%, which rules out occlusion under the light; RectLights are created without barn doors (`Lighting.cpp`).

## Then

- **Lumen 0.6x Karma (LGT-02).** Units and exposure match the Path Tracer; the deficit is indirect light. Hypothesis: zero-thickness Cornell walls and a light 1 mm under the ceiling starve Lumen's surface cache. Test with the Lumen Scene debug view and a light moved 5 cm down before changing code. Also: offline Lumen runs at game quality (UE-06, UE-08).
- **Viewport/husk parity (HOU-02).** The cooked material library, live Substrate, `hdue:asset` proxies and `op:` images exist only in the GUI host. Anything that changes the picture must live in USD or the delegate.
- **Geometry correctness (HYD-04, HYD-07, HYD-10).** Subdiv tags and face-varying topology, dirty-bit aware Sync (transform edits re-triangulate and re-upload today), curve widths/wrap/normals.
- **Framing (HYD-05 = HOU-08).** Data window, pixel aspect and framing are ignored: crops, overscan and husk tiling render wrong.
- **Materials and lights robustness (MAT-01, LGT-05).** One missing texture or one unsupported light attribute fails the whole batch; fall back per spec and warn instead. Light linking (LGT-04) is the largest missing feature.
- **Color (COL findings).** With UE's tonemapper on, a display-referred image is published as scene-linear and Houdini transforms it again.
- **Denoising (UE-07).** `r.PathTracing.Denoiser 0` is forced on every request, so UE's own denoisers never run.
- **Package hygiene (PKG-02, PKG-03 = HOU-05, HOU-12).** Ship a Test (not Development) runtime without `.lib`/validation layers/test modules; move logs and UE `Saved/` out of the install folder; stop putting `scripts/` first on `sys.path`.

## Cleanup (06, 07)

- **Move Houdini-only Python work behind the delegate (07 ALT-01–04).** Render settings pushed through a ctypes side channel, material preparation, `op:` textures, `hdue:asset` proxies and a 16 ms redraw timer all live in the Python host; Hydra already delivers or supports each. Fixing this also fixes HOU-01, HOU-02 and HOU-04.
- **Per-frame and per-tick waste (07 EFF-01–04).** `opdef:` images read and hashed every tick, single-threaded OCIO over every frame, a half → float → half beauty round trip, serial mesh conversion under the state lock.
- **One API table instead of 12 versioned extensions (06, 07 SIM-01).** Removes ~400 lines of loaders, exports and Python mirrors that have already drifted.
- **Dead code and scripts (06).** Nine unused `generate_*.py` fixture generators, unreferenced tests (`tests/substrate_vop_test.py`, `scripts/test_usd_materialx_export.py`, `tests/houdini_baseline.py`), `scripts/preview_pfm.py` (and with it Pillow), nine near-identical usdview `Test-*.ps1` wrappers. Net about -1630 lines.
- **Long functions (07 SIM-02–04).** `Pass::_Execute` (~485 lines), backend `Draw` (~224), `Mesh::Sync` (~188).
