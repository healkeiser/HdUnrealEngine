# Cameras

Cameras use Hydra's projection as is, so the conformed window, aperture offsets (lens shift) and orthographic projection match Karma; orthographic depth spans the camera's clipping range.

Framing is honoured: UE renders exactly the data window into the render buffer, with the projection remapped to it (Hydra's `CameraUtilFraming`, or under husk the render settings' `resolution`, `dataWindowNDC`, `pixelAspectRatio` and `aspectRatioConformPolicy`). Crops, husk tiles, overscan and non-square pixels therefore match Karma, and depth, AOVs and IDs follow the same window. Render buffers are limited to UE's largest 2D texture (`GetMax2DTextureDimension()`: 16384 pixels per axis on D3D12, `D3D12_REQ_TEXTURE2D_U_OR_V_DIMENSION`), which a larger request reports; render larger images in husk tiles (`--tile-count`), each within the limit. Realtime frames wider or taller than half that limit trace MegaLights at half resolution (`r.MegaLights.DownsampleMode` 2, UE's Epic level) when it was set to full resolution (Cinematic): its light sample buffer is twice the view there, and UE clamps it to the largest texture, lighting only part of the image (UE raises Lumen's screen probe downsampling for such views the same way). Realtime effects that work in screen space (Lumen screen traces, bloom, temporal anti-aliasing) only see the data window, so tile edges can differ slightly from a full frame; the Path Tracer does not.

The camera's near clip applies in both modes; its far clip does not: UE's views keep an infinite far plane (a finite reversed-Z far plane changed Lumen's lighting by 8% on Cornell with nothing beyond it), and UE's Path Tracer starts primary rays with an unbounded `TMax` (`PathTracing.usf`).

`fStop` and `focusDistance` drive UE's physical depth of field; the render settings' `disableDepthOfField` turns it off. `disableMotionBlur` (and the deprecated `instantaneousShutter`) turn motion blur off, UE's post-process motion blur included: its `MotionBlurAmount` is the camera's shutter interval in frames (UE's shutter fraction, as Movie Render Queue reads it), split over the motion samples, unless `unreal:postProcess:MotionBlurAmount` is authored; and `includedPurposes` narrows the purposes husk renders (its `--purpose`). Houdini's viewport draws the purposes its display options show (render by default, as for Karma), whatever the stage's render settings include, so switching a heavy scene's viewport to proxy works. Final renders resolve material bindings for the first of the render settings' `materialBindingPurposes`, else `full`, then allPurpose. In husk, hdUE's warnings print as `hdUE warning:` lines, once each. Lens attributes follow USD's convention of tenths of a scene unit, as Hydra and Karma read them (a `focalLength` of 35 in a metres stage is a 3.5 m lens). The Path Tracer ray-traces the thin lens (reference DOF); realtime uses UE's post-process DOF, which approximates it and clamps very large blur.

The camera's `exposure` (Hydra's linear exposure scale) scales the beauty, as Karma does, and leaves AOVs untouched; with UE's tonemapper on it is added to `AutoExposureBias` instead. Split diopters are not translated.

**Lens distortion** is UE's own: the spherical model of UE's CameraCalibrationCore plugin (Brown-Conrady, unitless `K1`, `K2`, `K3`, `P1`, `P2`), authored on the USD camera as `unreal:lensDistortion:K1` ... `P2` and `unreal:lensDistortion:PrincipalPoint` (float2, normalized image coordinates, (0.5, 0.5) by default), the values UE's Lens Distortion component and lens files take. As in UE, the view renders the model's overscan and UE's upscale pass distorts it, in both modes and for every AOV; the `depth` AOV stays undistorted. UE needs no Lens File for it (its docs: a handler "without the need to specify a Lens File"). Hydra's own `lensDistortion:*` camera attributes are not read: OpenUSD does not define the mathematics of its `standard` model, so no mapping to UE's could be checked. Orthographic cameras are not distorted.
