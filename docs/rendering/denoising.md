# Denoising

The Path Tracer denoises its last sample as UE does by default: **Denoiser** (`unreal:postProcess:PathTracingEnableDenoiser`, on) runs UE's NNEDenoiser plugin (`r.PathTracing.Denoiser.Name`, `NNEDenoiser`), which the runtime enables with its models (`/NNEDenoiser`, Open Image Denoise 2.3 networks run through ONNX Runtime on DirectML) and which reads the Path Tracer's own albedo and normal. The backend runs UE's active view extensions on every view family, as Movie Render Queue does (`MoviePipelineImagePassBase.cpp`): NNEDenoiser registers its denoiser from its extension. A host that exits with UE running (husk) ends in the backend's `DllMain`, before the backend's static destructors: UE's denoiser registry would otherwise release NNEDenoiser's ONNX Runtime session into DirectML and the GPU driver after the exit had ended UE's threads (a fail-fast, 0xC0000409). ONNX Runtime (`onnxruntime.dll`) is loaded before the backend (`src/client/backend.cpp`) so that it detaches after it; loaded later, it detached first and husk never exited. On the glossy Cornell box at 1920 x 1080 and 32 samples, it cut the noise (mean absolute Laplacian) from 0.00303 to 0.00015 with the mean brightness unchanged (0.0291, 0.0290). AOVs are not denoised and Lumen is unaffected; progressive viewport updates stay noisy until the last sample.

**Denoiser Plugin** (`r.PathTracing.Denoiser.Name`) picks NVIDIA's OptiX denoiser instead (UE's experimental OptiXDenoise plugin, on CUDA). UE does not stage the files that plugin loads from its `Source` folder (`OptiXDenoiseBase.dll` and its CUDA kernels, `OptiXDenoiserFunctionList.ptx`); `Stage-Runtime.ps1` copies them, and without the kernels the image stayed black. In UE 5.8.4 the plugin's default 256 x 256 tiles fail in the prebuilt library (`OPTIX_ERROR_INVALID_VALUE`) and leave a garbled 384-pixel strip, so the runtime sets `r.OptixDenoise.TileWidth` and `TileHeight` to 0, one call for the whole image. Same Cornell frame: noise 0.00009, mean 0.0291.
